How it works

One gateway in front of Codex

Every request passes through CodexGate. It checks who is asking and how much they have left, forwards the request, streams the answer back untouched and records what it used.

Two ways to use it

For a team, or just for you on every device

Team

A team on one API key

You pay for one OpenAI API account. Everyone gets their own login and limits.

  • Usernames, passwords, end dates with one-click renewal
  • Plans with 5-hour, daily, weekly or any rolling limits
  • Your key and organization never reach anyone
  • Disable one person and their Codex stops at once
Personal

Your own ChatGPT login, everywhere

Run Codex on your server with your own ChatGPT subscription, and pick it up from your phone or laptop.

  • Sign in once on the server; every session uses it
  • Devices like “Laptop” and “Phone”, each with its own limits
  • Tokens per task, so you see which job is expensive
  • Sessions keep running when the browser closes
One ChatGPT login is one person. This mode is for your own account, never for passing one subscription around.
Features

Everything a shared Codex needs, nothing it doesn’t

A small, readable stack: ASP.NET Core, SQLite and a panel with no build step.

Accounts and end dates

Admin or user, enable or disable, private notes, renew for 30, 90 or 365 days with one click.

Rolling limits

Any number of windows in tokens or dollars. Room frees up as old usage ages out, like ChatGPT’s own limits.

Limits Codex understands

When one is used up, Codex stops at once and says “Try again at 10:05 AM”.

Codex on the server

Start Codex or a shell on the server and use it from a web terminal. Each person runs under their own system account.

Devices new

Label where Codex runs and give each place its own limits. Keys and server sessions can each belong to one.

Own ChatGPT login new

Per plan: Codex uses each person’s own ChatGPT account. The gateway relays it unchanged, meters it, and never keeps the sign-in.

One-command install

Docker, free ports only, a setup page behind a one-time token, Let’s Encrypt over port 80 or Cloudflare DNS.

Usage and cost

Every request with its tokens and price, 30-day charts, totals by user and model, CSV export.

Several upstreams

Least-busy routing per model and automatic failover on 429, 5xx and network errors.

Personal keys

Install

Running in a few minutes

The installer sets up Docker if needed, builds CodexGate and prints one private link. The rest happens in your browser.

  1. Run one command as root

    It takes only free ports: the panel goes on 8443, and 443 or 80 stay with whatever already owns them. If your connection drops, it keeps going.

  2. Open the printed link

    The setup page opens only with its one-time token. Choose the admin, enter your domain and pick how to get the certificate.

  3. Get the certificate

    Over port 80 if it is free, or through Cloudflare DNS with an API token, which needs no port at all. It renews itself.

  4. Add people

    Make a plan, add users, and each one connects Codex with a single command from their own page.

On the server

bash <(curl -fsSL https://raw.githubusercontent.com/sadrazkh/CodexGate/main/install.sh)

Options

# the panel on 443 instead of 8443, if 443 is free
bash install.sh --https-port 443
# a memory cap (default: 60% of the server)
bash install.sh --memory 16g
# run it again later to update; your data is kept

Or with Docker by hand

docker build -t codexgate .
docker run -d --name codexgate --restart unless-stopped \
  -p 127.0.0.1:8080:8080 -v codexgate-data:/data \
  -e Gate__Upstreams__0__BaseUrl=https://api.openai.com/v1 \
  -e Gate__Upstreams__0__ApiKey=sk-... \
  codexgate
CI installs it on a fresh server whose port 443 is already taken, gets a certificate from a test authority, signs in and updates it in place, on every change.
Safe by default

Built to keep a shared key private

Your key stays on the server. Upstream errors are scrubbed of organization, project and key ids before anyone sees them.

Requests are checked and rewritten. One canonical body, no server-side storage, a private safety id per user, nothing that cannot be metered.

One system account per person. Server sessions cannot read each other’s files, the database or the gateway’s keys.

Keys stored only as hashes. Each server session has a key of its own that never appears on a command line.

Sign-ins that end when they should. Disabling a user or changing a password ends their sessions at once.

Browser hardening. Strict content policy, a CSRF header on every change, login throttling per address and per account.

FAQ

Good to know

Can my team share one ChatGPT Plus or Pro subscription through it?

No. Sharing one person’s ChatGPT login between several people breaks OpenAI’s terms and gets accounts banned. For a team, CodexGate uses an OpenAI API key. The “own ChatGPT login” mode is for each person’s own account, or one person on several devices.

Will it break x-ui or another service on my server?

The installer takes only ports that are free and runs CodexGate in Docker on its own network. If something already owns 443 or 80, it is left alone and the panel uses 8443. Sessions cannot reach the host’s loopback.

Which Codex clients work?

The Codex CLI, the desktop app and the VS Code extension all read the same ~/.codex/config.toml, which the ready-made command writes for you (your old file is kept as .bak).

Can I use it from my phone?

Yes. The panel works on a phone, and with server sessions Codex runs on the server while you watch and type in a browser tab. Close the tab and it keeps working; open it again from any device and you see the same screen.

How are tokens counted against a limit?

Fresh input and output count in full; cached input counts at 0.1 by default, since the API bills it at about a tenth. Dollar limits use the price table you set. Requests already running count at the user’s recent average.

What if my SSH connection drops during the install?

The installer keeps going on the server. Reconnect and read /var/log/codexgate-install.log; running the command again while it is still busy just shows its progress.

Where is my data, and how do I back it up?

Everything is in one SQLite database next to the cookie keys and the certificate, in a Docker volume. An admin can download a consistent copy from the panel at any time.
