# اجرای Codex روی سرور

[English](remote.md) · **فارسی**

با جلسه‌های سرور، هم‌تیمی در پنل به بخش **سرور** می‌رود، یک جلسه می‌سازد و داخل مرورگر یک ترمینال کامل می‌گیرد که روی سرور Codex یا یک shell ساده اجرا می‌کند. بستن مرورگر یا خاموش شدن لپ‌تاپ جلسه را متوقف نمی‌کند. با باز کردن دوباره، از لپ‌تاپ یا گوشی، همان صفحه دیده می‌شود. Codex داخل جلسه هم مثل هر Codex دیگری از درگاه رد می‌شود، پس سهمیه‌ی پلن هم‌تیمی رویش اعمال می‌شود.

## جداسازی

- هر هم‌تیمی که از جلسه‌های سرور استفاده کند، یک حساب سیستمی جدا به اسم `cg-<شماره>` می‌گیرد، با پوشه‌ی خانه‌ی خصوصی (`/home/cg-<شماره>` با دسترسی ۰۷۰۰). پروژه‌هایش در `~/work/<پوشه>` است.
- جلسه‌ها داخل tmux و با همان حساب اجرا می‌شوند. Codex یک نفر نه به فایل‌های بقیه دسترسی دارد و نه به پوشه‌ی داده‌ی درگاه (دیتابیس و کلیدهای کوکی). آن پوشه مال کاربر خود درگاه است، با دسترسی ۰۷۰۰. متغیرهای محیطی درگاه، از جمله کلیدهای سرویس مدل، به جلسه‌ها نمی‌رسد.
- root فقط برای ساختن حساب و جابه‌جا شدن به آن لازم است. این کار مال یک اسکریپت کوچک است: [`deploy/codexgate-host`](../deploy/codexgate-host). درگاه فقط همین را می‌تواند با `sudo` اجرا کند و هیچ کار دیگری را با root نمی‌کند. اسکریپت هر ورودی را با الگوی سخت‌گیرانه چک می‌کند و هیچ چیزی را به shell نمی‌دهد.
- ترمینال مرورگر با یک بلیت یک‌بارمصرف وصل می‌شود که بعد از ۶۰ ثانیه باطل است. گرفتن بلیت به کوکی پنل و هدر CSRF نیاز دارد.
- هر حساب سرور کلید درگاه خودش را دارد، به اسم «Server sessions». اگر باطلش کنید، جلسه‌های سرور تا شروع بعدی کار نمی‌کنند و آن شروع یک کلید تازه می‌سازد.

## راه‌اندازی با Docker (ساده‌ترین)

<div dir="ltr">

```bash
docker build -t codexgate-remote --target remote .
docker run -d --name codexgate --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v codexgate-data:/data -v codexgate-homes:/home \
  -e Gate__Upstreams__0__BaseUrl=https://api.openai.com/v1 \
  -e Gate__Upstreams__0__ApiKey=sk-... \
  codexgate-remote
```

</div>

این image همه‌چیز را دارد: tmux، Git، Node.js، Codex و اسکریپت کمکی. جلسه‌های سرور هم در آن روشن است. `/home` را روی volume نگه دارید، چون پروژه‌های هم‌تیمی‌ها آن‌جاست. با ری‌استارت کانتینر، جلسه‌های در حال اجرا تمام می‌شوند و فایل‌ها می‌مانند.

کانتینر را با `--security-opt no-new-privileges` یا فایل‌سیستم فقط‌خواندنی اجرا نکنید، چون اسکریپت کمکی به `sudo`، `useradd` و `runuser` نیاز دارد. سقف حافظه‌ی هر کاربر داخل کانتینر اعمال نمی‌شود. به‌جایش با `--memory` برای کل کانتینر سقف بگذارید.

## راه‌اندازی مستقیم روی سرور لینوکس

به tmux نسخه‌ی ۳.۲ یا بالاتر، `sudo`، Codex (`npm install -g @openai/codex`) و Git نیاز دارید.

<div dir="ltr">

```bash
sudo useradd --system --create-home --home-dir /var/lib/codexgate codexgate
sudo deploy/install-remote.sh codexgate
```

</div>

CodexGate را با کاربر `codexgate` و این تنظیمات اجرا کنید:

<div dir="ltr">

```bash
Gate__Remote__Enabled=true
Gate__Remote__GatewayUrl=http://127.0.0.1:8080/v1
```

</div>

با systemd، **سقف حافظه‌ی** پلن برای هر کاربر اعمال می‌شود: جلسه‌های هر حساب داخل یک scope زیر `codexgate.slice` با `MemoryMax` اجرا می‌شوند.

## روشن کردن برای یک پلن

**پلن‌ها ← ویرایش ← جلسه‌های روی سرور**: اجازه را بدهید، تعداد جلسه‌ی هم‌زمان هر کاربر را تعیین کنید و اگر خواستید سقف حافظه بگذارید. بخش **سرور** برای کاربران آن پلن ظاهر می‌شود.

## نکته‌ها

- جلسه‌ی «ترمینال» برای `git clone`، نصب ابزارهای پروژه یا هر کار دستی است. هم‌تیمی برای push به مخزن خصوصی می‌تواند داخل حساب خودش کلید SSH بسازد.
- توقف جلسه، برنامه‌های داخلش را می‌بندد ولی فایل‌های `~/work` می‌مانند. حذف کاربر در پنل جلسه‌هایش را متوقف می‌کند، ولی حساب و فایل‌هایش روی سرور می‌ماند.
- اگر پنل گفت سرور نتوانست جلسه را آماده کند، لاگ درگاه را ببینید. `sudo: a password is required` یعنی خط sudoers نصب نشده. `no such file` یعنی اسکریپت کمکی نصب نشده.
